# Development

Requires Node.js 22 or later. Node.js 24 LTS is recommended. No package installation is needed.

```sh
git clone https://github.com/sasha-gladkikh/gregor-puzzles.git
cd gregor-puzzles

npm start          # Build and serve at http://localhost:4173
npm test           # Game, build, and server checks
npm run build      # Generate dist/ for hosting
```

Use `npm start -- --port=4174` if the default port is occupied. Stop with **Ctrl+C**; restart after edits. The local server serves only `dist/` and listens on `127.0.0.1`.

## Structure

- `game/`: game, collection, field guide, scientific profiles, editorial review, and illustrations.
- `scripts/`: build and local server.
- `tests/`: game logic, build integrity, and server checks.
- `docs/`: scientific rationale, review instructions, and development notes.
- `.github/`: automated checks and feedback forms.

The ten-round catalog is in `game/rounds.mjs`; clinical profiles, completion-card text, and vocabulary are in `game/clinical.mjs` and `game/hpo-terms.mjs`. Illustration metadata and image-note positions are in `game/artwork-data.mjs`; each note appears when the piece containing its point is placed. Mechanism figures and the spliceosome comparison are in `game/mechanism.mjs`. Scientific sign-off and the `requireApproval` switch are in `game/signoff.mjs`. Saved progress uses stable round IDs, so earlier saves still load. Earlier design experiments remain in Git history.

Keep repeated content to a minimum: one completed gene–condition summary, one illustration guide, and one external link per reference within each round. Group related findings under shared headings and citations. Repeat navigation only where it helps people move through the site.

The homepage uses `game/home-demo.mjs` for a final-piece interaction and a brief, illustrative channel-motion sequence. It never changes game progress. `game/puzzle-geometry.mjs` supplies the same piece paths to the preview and game. The visible diagram in `game/home-map.mjs` groups the currently playable rounds by process; it is a conceptual navigation aid, not a complete anatomical model. `game/home-explore.mjs` adds collection progress, a local-date daily pick, and short previews using the existing artwork renderer. Only one preview plays at a time, for seven seconds; offscreen and reduced-motion states stop playback. `game/journeys.mjs` shares the approved three-round routes between Home and the game, with route context in the URL.

The build generates `home-data.mjs` from the playable catalogue, prerenders homepage navigation, and filters static featured cards and process links through `scripts/homepage.mjs`. This keeps the no-JavaScript fallback within the same approval boundary. The public player summary loads when the leaderboard approaches the viewport. Header, hero, preview, and mobile Play links share the same saved-progress destination. The printed root-URL QR code is unchanged.

The shared shell is in `game/site.mjs` and `game/site.css`: linked Stanford affiliation, Home / Play / Collection / Science navigation, and the project footer. `game/about.html` describes the project. The original logo remains in `game/icons/`; its display frame crops transparent vertical padding without stretching the artwork. Source Sans 3 is self-hosted in `game/fonts/`, with Adobe source details and the SIL Open Font License.

`game/share-card.mjs` creates a 1600-pixel-wide PNG from a completed illustration, gene, condition, and actual collection progress. Native file sharing, download, and copying the homepage link are available without a service connection. Names and times are excluded.

`game/play.css` controls the responsive board, adjacent desktop tray, phone layout, completion card, and Focus view. The completion summary pairs gene, condition, and one memory connection beside the desktop illustration or below the phone image; clinical context and previous clues remain expandable. `game/experience.mjs` contains synthesized audio with a saved mute preference and the collection logo animation.

`game/discovery-motion.mjs` animates new clues from the placed piece into stable keyed rows. A fine SVG connection carries a light signal to the destination, followed by an arrival accent; no acknowledgment is required. `game/play-learning.mjs` keeps the latest clue's title and first sentence beneath the board on narrow layouts and in Focus view. The animation targets that preview when visible; the complete list remains available through **Clues**. Scrolling, dialogs, and reduced-motion preferences cancel only the visual effect.

`game/gene-bank.mjs` offers optional gene recognition with an explicit notice that a correct answer completes the round. `game/engine.mjs` sequences the hint content in `game/gene-hints.mjs` through three stages: location/function, a biological connection, and symbol help. Each requested stage counts once and persists across reloads. Hint migration preserves previously exposed symbol help without adding a charge. Correct identification adds a brief explanation of how the clues fit. There are no piece-placement hints.

`game/session.mjs` separates browsing interactions from accepted progress. Mode choice stays available until the first correct placement or accepted gene answer, which starts a timed clock. Hints, reference views, selection, and wrong answers do not start it. Saved tray permutations preserve piece letters and order across reloads; older saved progress and running clocks remain readable.

`game/piece-motion.mjs` normalizes tray and board SVG geometry before animating a piece, accounting for letterboxing. Its cancellable settlement promise triggers contact audio and the completed-illustration reveal. Scroll, resize, dialogs, reset, and visibility changes remove transient pieces and restore the placed image. Audio prepares during the initiating user gesture; placement sounds and the completion chord follow contact. Cancellation and mute invalidate pending sound. Completing in Focus view preserves the board size and places the illustration guide below it.

`game/artwork-motion.mjs` animates the completed illustration inside the puzzle board. The ten scenes in `game/artwork-motion-data.mjs` use cutouts from the original artwork over localized clean background patches in `game/artwork/motion/`. Original images remain unchanged. New completions animate after the final piece settles, with pause/resume controls beneath the image; returning to a completed round does not autoplay. A one-time perimeter trace, halo, and soft light sweep accompany a gentle lift of the actual board frame. Decorative effects settle within three seconds, then stop updating. The frame, depth shadow, and 48 original-pixel cutouts share one playback clock, so pausing also freezes the entrance and floating frame. Cargo begins at its original position, departs with a short stagger, follows its route at an approximately constant speed, and returns only while invisible. Floating components blend smooth rhythms rather than stopping at common waypoints. Native-derived contours in `game/artwork-particle-contours.mjs` and `game/artwork-object-contours.mjs` retain the original outlines while excluding surrounding background from moving cutouts. Cleanup masks keep both the original and refined extraction footprints and add a constant 3 px clearance before feathering; the two measured lysosomal shadows use 6 px and 9 px. The central synaptic vesicle has a separately measured shadow footprint. This removes stationary outline remnants along concave proteins and thin neuron branches; enlarging a shape from its center does not provide that clearance. The lower lysosomal cargo finishes before reaching the fixed exterior molecule. During the first 120 ms, the moving layer crossfades at the exact original pose; motion then joins smoothly over 480 ms, avoiding doubled contours. Detached objects receive subtle pointer parallax; the whole frame also tilts by less than one degree. The same clock drives staged contour lighting in `game/artwork-detail.mjs`, with per-scene paths in `game/artwork-detail-data.mjs` and `game/artwork-detail-membranes.mjs`. Routes follow existing arrows; surface reflections alternate direction across RNA, protein folds, membranes, and vesicle rims. Highlights on moving structures inherit their transforms. These are visual emphasis, not new molecules or measured reaction timings. The round 08 joined exon uses smooth native-source contours and a mask extended beyond the cropped edge. The current round’s assets preload after the first interaction. Hidden tabs, dialogs and offscreen playback pause motion. Opening an image note restores the still image for reading. Reduced-motion preferences keep the original still image. Preparing and retry states keep playback status explicit. Asset failures also preserve the still image. The board, reference, and moving cutouts share native lossless WebP masters through `game/artwork-source.mjs`: 1448 × 1086, or 1447 × 1087 for round 05. These preserve every original PNG pixel and provide about 46% more pixels than the 1200 × 900 thumbnail renditions. All board layers use the same 4:3 mapping, including round 05. Science and guide figures use responsive sources; collection thumbnails retain the smaller files. Native dimensions and pixel checksums are recorded in `docs/artwork-resolution.json`. Perimeter effects are vectors; enlarging the figure does not invent additional source detail. Sequences are illustrative, not molecular simulations: fixed DNA-repeat diagrams never grow, and released RNA products remain distinct from active spliceosome structures. The background patches were generated from the source images; moving structures use the original pixels. Generation prompts and visual QA are recorded in `docs/artwork-motion.json`.

`game/figure-view.mjs` moves the same board, renderer, and playback controls into the enlarged view. A placeholder preserves the original layout. Previously playing artwork resumes there; paused artwork stays paused. Close or Escape pauses playback and restores the original positions and focus. No second renderer is created. A queued close event from a previous opening cannot detach a newly reopened figure.

`game/artwork-guide.mjs` adds a finite three-note sequence to the original completed image, using the existing cited landmarks and the artwork's playback clock. Captions reserve their tallest natural height to avoid layout jumps. Once the sequence finishes, its highlights stop and ambient artwork motion continues. The guide can be replayed; pausing, dialogs, and enlargement share the same clock. Reduced motion presents a static takeaway, with the full notes still readable in **Revisit your clues**.

`game/science.mjs` and `game/science-ui.mjs` provide searchable gene profiles, interactive figures, and deduplicated references. Shared citation helpers in `game/clinical-ui.mjs` assign stable reference numbers; each external paper appears once per round, with compact links from the relevant content. Symptoms share a citation at the system heading when their sources match; different evidence stays attached to the corresponding finding. `game/review.mjs` presents player-facing wording for editorial review. Both pages expose full scientific content independently of game progress. The sign-off checklist remains in `game/signoff.mjs`; the public interface displays no approval labels.

`game/collection-page.mjs` renders the collection and process map. In the game, progress updates separately from the Browse rounds cards; cards render only when requested and their images load lazily. `game/collection-data.mjs` defines related rounds and shared guide helpers. `game/field-guide.mjs` renders printable pages for completed rounds only, using the existing `collectionProgress` reader. The process map organizes illustrated processes; it does not assert exclusive localization or direct interaction. Existing round IDs, storage keys, and save migration remain unchanged.

The QR code in `game/icons/` was generated with macOS Core Image and verified by decoding; regenerate it if the hosted address changes. See [BOOTH.md](BOOTH.md) for conference setup and device testing.

## Publishing

The GitHub repository is public. GitHub Pages publishes only the generated `dist/` files. No source workbook, family identifiers, individual variants, or development documents are included in the game build.

All HTML pages include a `noindex` robots meta tag. This asks supporting search engines not to list the game; it does not restrict access or prevent link forwarding. The public GitHub repository can still be found in search. Do not block crawling in `robots.txt`, because crawlers must read the noindex directive.

The **Check and publish** workflow tests and builds every push to `main`, then deploys the game to [GitHub Pages](https://sasha-gladkikh.github.io/gregor-puzzles/). Pull requests run checks without deploying. The repository's Pages source must be **GitHub Actions**. No separate hosting account is needed.

## Validation and limits

GitHub Actions runs tests and a build for pushes and pull requests. Checks cover placement, reveals, image-note placement, gene entry and previous symbols, new-player reset, sign-off gating, source traceability for completion cards and figures, picture completion, timing, save migration, all ten rounds, published file references, and the local server.

Browser checks cover completion, review navigation, reload restoration, and phone-width layouts. Sequence tests cover idle startup, manual navigation, pause/cancellation, finite walkthroughs, continuous artwork loops, bounded parallax, asset-cache retry, and duplicate play requests. Sound is on by default and plays only after a user gesture; a saved mute preference is respected. No audio files or external services are used for sound. These do not replace physical iPhone/Safari or full accessibility testing. Scientific review remains pending.

Progress stays in browser storage and does not sync between devices. Moving from a local preview to the hosted URL starts separate progress. Clearing browser data removes it. Collection and field-guide pages read those same saved rounds; they do not create a separate progress format. Timing is measured in the browser. Optional named players sync attempt records to a separate private Google Form; the public leaderboard exposes only player summaries and best qualifying times. Browser-held random credentials keep duplicate display names separate. Switching devices or clearing browser data creates a new identity. Practice and gene-answer completions count toward progress but not timed image rankings. Attempt tracking starts with this release; overwritten older attempts cannot be recovered. Puzzle suggestions use a branded website form connected to an anonymous Google Apps Script receiver, which stores private Google Forms responses. Name and email are optional, and sign-in is not required; see [COMMUNITY.md](COMMUNITY.md). There is no game account sign-in or third-party analytics. Players explicitly join before attempt records are sent to the team.
